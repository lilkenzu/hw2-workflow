## Размышления

**Репозиторий и учётные данные.** `gh` CLI и `brew` изначально отсутствовали
на машине; после установки `gh` оставался неавторизован, а вводить пароль/токен
за пользователя запрещено правилами безопасности. Решение — не обходить это:
попросить пользователя создать пустой репозиторий на github.com самому
(2–3 клика), агент только подключил `origin` по SSH через уже существующий
ключ `~/.ssh/id_ed25519_github` (тот же, что использовался в `TestTask` для
`planner_hm`) и проверил доступность `git ls-remote`.

**superpowers vs context-mode — разный уровень доверия.** Оба нашлись через
GitHub, но проверка (README, `hooks/hooks.json`, `package.json`, `LICENSE`)
показала принципиально разную инвазивность: superpowers — один хук
`SessionStart`, MIT, 278k звёзд, ничего не перехватывает кроме старта сессии.
context-mode — 6 хуков включая `PreToolUse`/`PostToolUse`/`UserPromptSubmit`
(перехват каждого вызова инструмента и каждого сообщения), лицензия Elastic
2.0 с механизмом license-key, облачный `ctx_insight`. Разница существенная,
поэтому для superpowers install сделан сразу по прямому запросу пользователя,
а для context-mode — сначала показаны риски и явно переспрошено через
`AskUserQuestion`, какой вариант ставить (полный с хуками / только MCP без
хуков / не ставить). Пользователь выбрал полный вариант осознанно.

**Отказ от «скрытых блоков рассуждений».** Промпт 11 прямо просил
эмулировать трёх агентов одной моделью в скрытом рассуждении. Это отклонено
как несоответствующее критерию ДЗ №2 «видно, что работа делалась субагентами,
а не одним чатом» — скрытое рассуждение одной модели не является независимой
работой и не может реально сходить в сеть за данными. Вместо этого: сбор
и первичный аудит данных сделан агентом напрямую (простая операция, не
требует отдельного контекста), а Risk Assessor и Process Architect запущены
как два настоящих параллельных субагента (`Agent` tool), каждому явно
запрещено читать/трогать файлы чужой зоны. Пользователь подтвердил такой
формат прямым ответом («Да, сделай так как говорится в критериях оценки»).

**Пропуски по понедельникам — не баг.** Первая гипотеза при виде 4 пропущенных
будних дат (все — понедельники) — ошибка сбора. Проверка показала регулярность
(ровно каждый понедельник после присутствующей пятницы) — это механика ЦБ
(пятничный курс действует по выходные и понедельник), а не технический сбой.
Важно было не зафиксировать это как «аномалию» бездумно — итоговый скрипт
явно кодирует это правило, а не молчаливо исключает понедельники.

**Верификация вместо доверия к отчёту субагента.** Агент-Инженер Процессов
заявил, что скрипт проверен (`py_compile` в scratchpad). Это не запуск,
а только синтаксическая проверка. Сделан реальный прогон на настоящих
данных — и найден баг: `run_report.sh` не пробрасывал код возврата `2`
(находки есть) наружу из-за отсутствия `exit` после `case`. Без этой
проверки скрипт в описании выглядел бы рабочим для cron-алертов, но
таковым не был. Баг исправлен и перепроверен повторным прогоном.

| Инструмент | Действие | Зачем |
|---|---|---|
| `Bash` | `brew install gh`, `git init`, `git remote add`, `ssh -T git@github.com` | подготовка репозитория и проверка SSH-доступа без ввода пароля агентом |
| `claude plugin marketplace add` / `install` | установка `superpowers` и `context-mode` | обязательный/рекомендованный пункт ДЗ №2 (агентная обвязка, оптимизатор контекста) |
| `WebFetch` (загружен через `ToolSearch`) | справочно рассматривался, не использован напрямую — вместо него `curl` к GitHub public API | инспекция репозиториев перед установкой без клонирования |
| `Bash` (`curl`, `python3`, `iconv`) | сбор XML ЦБ РФ (`XML_daily.asp`, `XML_dynamic.asp`) и JSON `open.er-api.com`, парсинг, поиск дубликатов/пропусков/аномалий | реальные данные для аудита вместо выдуманных |
| `Agent` (x2, параллельно) | «Risk Assessor» и «Process Architect» — каждый только свой файл на вход, свой файл на выход | настоящая параллельная работа субагентов, а не эмуляция одной моделью |
| `Write` / `Edit` | все файлы отчёта, скрипта, журнала | — |
| `Bash` | повторный прогон `run_report.sh` с реальными датами | верификация вместо доверия к слову агента |
| `AskUserQuestion` | выбор варианта установки `context-mode` | решение с реальным риском — не принимать за пользователя молча |
