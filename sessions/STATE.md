## Известные проблемы

- Режим разрешений этой сессии не был зафиксирован явно в начале работы
  (в отличие от `TestTask`, где пользователь осознанно выбрал ручной режим).
  По косвенным признакам — не `bypassPermissions`, но точный режим не
  подтверждён. Зафиксировать явно в следующей сессии.
- `context-mode` меняет поведение по умолчанию (маршрутизация вывода
  инструментов через `ctx_execute`/`ctx_batch_execute`) — при работе с
  реальными сетевыми данными ЦБ в этой сессии агент сознательно продолжил
  использовать обычный `Bash`/`curl` напрямую, а не `ctx_*`-обёртки, так как
  объём вывода был небольшим и точность важнее экономии контекста на этом
  шаге. Это решение не было явно согласовано с пользователем — заметка на
  будущее.
- `materials/` содержит сырые XML/JSON как есть — не проверялись на
  чувствительные данные (для открытого источника ЦБ риска нет, но как
  общая практика перед push стоит перепроверить).

- **Проверка на секреты — финальная, расширенная, задокументирована файлом.**
  8 направлений: паттерны ключей/токенов (AWS/GitHub/Slack/OpenAI/Google/
  приватные ключи), файлы-кандидаты, история команд, **вся история git**
  (не только рабочее дерево — все 3 коммита), список когда-либо
  закоммиченных файлов, метаданные обоих PDF, бинарный grep по PDF/PNG на
  локальный путь/имя пользователя, сырые данные API на служебную обвязку
  curl. Везде чисто. Сырой вывод — `sessions/evidence.md` (новый файл,
  по образцу `TestTask/sessions/evidence.md`). Отмечено также в `README.md`
  и `REPORT.md`, не только здесь.
