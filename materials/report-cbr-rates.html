Краткое резюме

Данные ЦБ корректны и внутренне непротиворечивы — дубликатов нет, «пропуски» по понедельникам объясняются регламентом ЦБ, сверка с независимым источником расходится в пределах 0.1–0.25% (норма методологии фиксинга).

Найдено 2 дня с движением курса >2% (USD −2.08% 20→21.08, EUR +2.05% 27→28.08, последний — на конец периода) — не ошибка данных, а рыночная волатильность. Риск — в процессах, которые «запекают» вчерашний курс (биллинг, отложенная переоценка).

Главный вывод. Риск — не в самих данных ЦБ, а в наивном парсинге: без явной обработки кодировки, десятичного разделителя и номинала пайплайн может тихо упасть или дать неверный курс.

Собран и проверен вживую воспроизводимый скрипт: весь цикл (сбор → аудит → сверка → отчёт) — одна команда, готова к cron.

03 · Fix и автоматизация

Что делать — немедленно

  • Декодировать ответ ЦБ явно как cp1251 — никогда не полагаться на дефолтную кодировку
  • Всегда .replace(',', '.') перед float(), с логом при сбое парсинга, не тихим пропуском
  • Всегда делить Value / Nominal — без исключений «для текущего набора валют»
  • Зашить правило «понедельник после пятницы — норма» в логику проверки пропусков
  • Сделать сверку со вторым источником обязательным автоматическим шагом с порогом 1%

04 · Workflow

Запуск отчёта одной командой

Готовый воспроизводимый артефакт — не промпт, а детерминированный скрипт: пайплайн — ETL с фиксированными числовыми правилами, нужен одинаковый результат при каждом прогоне, а не переменная интерпретация модели. Проверен вживую — реальный прогон на реальных данных ЦБ, результат идентичен ручному анализу выше.

Файлы: workflow/cbr_report.py (логика) + workflow/run_report.sh (точка входа).

# произвольный период
./run_report.sh 29.07.2026 28.08.2026

# регулярный прогон, прошлый месяц
./run_report.sh --last-month

Коды возврата (проверены живым прогоном, включая фикс бага с непробрасыванием кода — см. журнал): 0 — находок нет, 2 — есть находки, требующие внимания, иное — сбой пайплайна.

# ежемесячно, 1-го числа в 09:00
0 9 1 * * /path/to/workflow/run_report.sh --last-month >> logs/cron.log 2>&1
Следующий раз аналитик просто подставляет период в команду выше и получает готовый отчёт — без ручного сбора XML, парсинга и сверки.
