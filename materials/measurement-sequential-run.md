# Замер: та же задача последовательно, без субагентов

Промпт из сопроводительных материалов курса: «Ту же самую задачу сделай сам,
последовательно, без субагентов. В конце скажи, сколько это заняло и сколько
контекста ушло». Вход — тот же `materials/audit-findings.md`, что получили
Риск-менеджер и Инженер процессов в параллельном запуске.

## Риск-менеджер (зона 2) — последовательно

| # | Находка | Приоритет | Обоснование |
|---|---|---|---|
| 1 | Кодировка windows-1251 | Средний | Ломает текстовые метаданные, не числа; риск — только если валюты матчатся по имени |
| 2 | Запятая как десятичный разделитель | Высокий | `float()` падает — весь курс на дату теряется, прямой путь к кассовому разрыву в биллинге/переоценке |
| 3 | `Value / Nominal` | Средний → высокий при росте списка валют | Для USD/EUR/CNY не сработало (Nominal=1), но структурный риск остаётся |
| 4 | Пропуски по понедельникам | Низкий | Механика ЦБ, не сбой — риск только для наивной валидации «запись на каждый будний день» |
| 5 | Скачки курса >2% (USD, EUR) | Высокий | Рыночная волатильность, риск для процессов с курсом «вчерашнего дня» |
| 6 | Сверка со 2-м источником (0.10–0.25%) | Низкий | В пределах нормы методологии фиксинга |

## Инженер процессов (зона 3) — последовательно

Fix-действия и архитектура workflow — по сути идентичны параллельному запуску
(декодировать `cp1251`, заменить запятую на точку, всегда делить на `Nominal`,
формализовать правило понедельника, сделать сверку обязательным шагом,
собрать в одну команду с кодами возврата под cron).

## Замер

| | Последовательно (в этой же сессии) | Параллельно (2 субагента) |
|---|---|---|
| Время | 53 секунды (11:56:43 → 11:57:36, замерено `date` до/после) на оба блока | Risk Assessor — 60.7 сек, Process Architect — 176.8 сек, выполнялись одновременно (общее время = дольше из двух ≈ 177 сек) |
| Контекст главной сессии | Рассуждение по обеим зонам прошло **прямо в основной сессии** — весь текст выше стал частью её контекста | Только краткие резюме (5 пунктов на каждого) вернулись в основную сессию; `subagent_tokens` — 46 942 (Risk Assessor) и 60 383 (Process Architect) — итого **107 325 токенов** остались изолированы в дочерних контекстах и не попали в основную сессию |
| Качество результата | Сопоставимое по содержанию — те же 6 находок, те же приоритеты | Более подробное: полное обоснование, отдельные файлы, у Инженера процессов — рабочий скрипт с реальным тестовым запуском |

## Честная оговорка

Это сравнение **нечистое**: к моменту последовательного прогона основная
сессия уже видела оба результата параллельного запуска (они использовались
для синтеза `REPORT-cbr-rates.md`) — контекст был «тёплым», задача решалась
не с нуля. На чистом замере (свежая сессия без предварительного контекста)
разница по времени была бы больше в пользу последовательного варианта на
такой маленькой задаче — ровно то наблюдение, которое прозвучало на занятии:
на небольшой задаче параллельный запуск не выигрывает по времени, выигрыш —
в контексте главной сессии. Здесь это видно даже нечисто: 107 325 токенов,
которые в параллельном варианте не попали в основную сессию, в
последовательном стали бы её частью.
