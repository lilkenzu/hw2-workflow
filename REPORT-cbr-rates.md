# Отчёт: курсы валют ЦБ РФ — сбор, проверка, расхождения

**Период:** 29.07.2026 – 28.08.2026 (23 рабочих дня) · **Валюты:** USD, EUR, CNY
**Источник:** официальный XML API ЦБ РФ, без ключей и регистрации · **Сверка:** open.er-api.com
**Подготовлено:** 3 специализированных агента (аудит данных → бизнес-риски → процесс/автоматизация), синтез — вручную

---

## TL;DR для руководителя

- Данные ЦБ **корректны и внутренне непротиворечивы** — дубликатов нет, «пропуски» по понедельникам объясняются регламентом ЦБ, сверка с независимым источником расходится в пределах 0.1–0.25% (норма методологии фиксинга).
- Найдено **2 дня с движением курса >2%** (USD −2.08% 20→21.08, EUR +2.05% 27→28.08, последний — на конец периода) — не ошибка данных, а рыночная волатильность. Риск — в процессах, которые «запекают» вчерашний курс (биллинг, отложенная переоценка).
- **Главный риск — не в самих данных ЦБ, а в наивном парсинге**: без явной обработки кодировки/десятичного разделителя/номинала пайплайн может тихо упасть или дать неверный курс.
- Собран и **проверен вживую** воспроизводимый скрипт: весь цикл (сбор → аудит → сверка → отчёт) — одна команда, готова к cron.

## 2. Где проблемы (бизнес-риск)

| Приоритет | Находка | Затронутые процессы | Почему |
|---|---|---|---|
| 🔴 Высокий | Запятая как разделитель | Переоценка активов, биллинг, кассовые разрывы, отчётность | Останавливает получение курса целиком — отсутствие курса на дату при ежедневной зависимости от него |
| 🔴 Высокий | Скачки >2% (USD, EUR) | Биллинг, кассовые разрывы, переоценка активов | Подтверждённая волатильность; риск — в процессах, использующих курс предыдущего дня без пересчёта |
| 🟡 Средний | Кодировка + логика `Value/Nominal` | Переоценка активов, биллинг, отчётность | Не сработало на USD/EUR/CNY сейчас, но эскалируется до высокого при расширении списка валют |
| 🟢 Низкий | Пропуски по понедельникам | Ложные алерты валидации | Не сбой данных — сбой наивного мониторинга, ожидающего запись на каждый будний день |
| 🟢 Низкий | Расхождение со 2-м источником (0.1–0.25%) | — | В пределах нормы методологии фиксинга, не аномалия |

Полная таблица с обоснованием по каждому пункту: [`materials/risk-assessment.md`](materials/risk-assessment.md).

## 3. Что делать (fix + автоматизация)

**Немедленно:**
1. Декодировать ответ ЦБ явно как `cp1251` — никогда не полагаться на дефолтную кодировку.
2. Всегда `.replace(',', '.')` перед `float()`, с логом (не тихим пропуском) при сбое парсинга.
3. Всегда делить `Value / Nominal` — без исключений «для текущего набора валют».
4. Зашить правило «понедельник после пятницы — норма» в логику проверки пропусков, чтобы не плодить ложные алерты.
5. Сделать сверку со вторым источником обязательным автоматическим шагом с порогом 1%, а не разовой ручной операцией.

Полное обоснование: [`materials/process-workflow.md`](materials/process-workflow.md).

## ⚙️ WORKFLOW: запуск отчёта одной командой

Готовый воспроизводимый артефакт — не промпт, а детерминированный скрипт (обоснование: пайплайн — ETL с фиксированными числовыми правилами, нужен одинаковый результат при каждом прогоне, а не переменная интерпретация модели). **Проверен вживую** — реальный прогон на реальных данных ЦБ, результат идентичен ручному анализу выше: [`workflow/report_2026-07-29_2026-08-28.md`](workflow/report_2026-07-29_2026-08-28.md).

Файлы: [`workflow/cbr_report.py`](workflow/cbr_report.py) (логика) + [`workflow/run_report.sh`](workflow/run_report.sh) (точка входа).

**Запуск:**
```bash
cd workflow
chmod +x run_report.sh
./run_report.sh 29.07.2026 28.08.2026     # произвольный период
./run_report.sh --last-month               # прошлый календарный месяц — для регулярного прогона
```

**Коды возврата** (проверены живым прогоном, включая фикс бага с непробрасыванием кода — см. журнал): `0` — находок нет, `2` — есть находки, требующие внимания, иное — сбой пайплайна. Готово для cron:
```
0 9 1 * * /path/to/workflow/run_report.sh --last-month >> logs/cron.log 2>&1
```

Следующий раз аналитик просто подставляет период в команду выше и получает готовый `report.md` — без ручного сбора XML, парсинга и сверки.
